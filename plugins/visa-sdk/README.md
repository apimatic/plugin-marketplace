# Visa/CyberSource SDK Assistant (Claude Code plugin)

A Claude Code plugin that helps developers **install and consume the Visa/CyberSource Merged Spec .NET
SDK** (the APIMatic-generated C# SDK at
[asadali214/visa-cybersource-sample-sdk](https://github.com/asadali214/visa-cybersource-sample-sdk)),
plus reusable guidance for working with **any APIMatic-generated .NET SDK**.

The **SDK map is bundled with the plugin**, and a single `visa-sdk` agent grounds every fact in it —
cloning the SDK source only when the map can't settle a fact. Structure adopted from the `twilio-sdk`
and `maxio-sdk` plugins (an `integrate-visa` router plus one `visa-sdk` agent).

## The SDK map (bundled; source cloned only on a gap)

The generated table-of-contents ships inside this plugin (`skills/visa-getting-started/sdk-map.md`
plus `map/` branch pages):

- **`map/operations/`** — one page per controller (49 pages, 135 operations, spanning the merged
  CyberSource surface — Payments, Capture, Refund, Reversal, Void, Invoicing, Invoice Settings,
  Token Management, Subscriptions and Plans, Decision Manager, Reporting, Transaction Search,
  Microform and the rest): exact C# signature, must-pass-explicitly params, return type, error case
  (typed vs `RawError`) with its accessors, and pagination — plus the source file each came from.
- **`map/models/`** — record models (eleven alphabetical pages, 1,972 records), `OneOf`/`AnyOf` unions
  (none in this SDK), and full enum value lists.

`sdk-map.md` records the source commit it was generated from (the map is generated from the SDK
source, which remains the ground truth; the SDK repo and the map regenerate together). The agent
**navigates by map lookup instead of grepping**: it answers most questions from the map directly —
field lists with JSON wire names, error accessors, enum values — and only when the map can't settle a
fact does it clone the SDK source (tag `v2.0.0`, the ref the map was generated from) and open the one
file the map names. Grepping / globbing / `find`-ing the tree to locate something is a defect — the
map is the locator.

> **This SDK is large.** 1,972 record models across eleven pages, and 135 operations across 49
> controllers. Open the one page a lookup needs; reading the map front to back is neither necessary
> nor affordable.

## Two layers

The Visa/CyberSource .NET SDK is generated by the [APIMatic](https://www.apimatic.io/) code
generator, which emits the same cross-cutting shape for every .NET SDK it produces. The plugin
reflects that:

| Layer | Skill(s) | Names used |
| --- | --- | --- |
| **SDK-specific** (entry point) | `visa-getting-started` (+ the bundled SDK map) | Concrete names (`CyberSourceMergedSpecClient`, `CyberSourceMergedSpecClientOptions`, …) |
| **SDK-specific** (auth) | `dotnet-authentication` — see the caveat below | Concrete names (`VisaHttpSignatureHook`, `VisaHttpSignatureConfigResolver`, …) |
| **API-agnostic usage** | `dotnet-client-initialization`, `dotnet-calling-endpoints`, `dotnet-models`, `dotnet-error-handling`, `dotnet-configuration-resilience`, `dotnet-testing` | Placeholders (`{Api}Client`, `{Api}ClientOptions`, `{RootNamespace}`, …) so they apply to *any* APIMatic .NET SDK |

The six agnostic skills never name Visa or CyberSource — not in their bodies and not in their
`description` frontmatter, which says "an APIMatic-generated .NET SDK". They describe the generator's
patterns so they apply to whatever APIMatic .NET SDK your project consumes, **and so they can be
copied into another APIMatic plugin unedited**. Where an SDK map ships (as it does here, bundled),
they defer to it for lookup before touching the SDK source.

> ⚠ **`dotnet-authentication` is the one exception in this plugin, and it is NOT portable.** In every
> other `plugins/*-sdk` this skill is part of the agnostic layer, describing the credentials-property
> pattern APIMatic generates from a spec's security scheme. **This merged spec declares no security
> scheme at all**, so `CyberSourceMergedSpecClientOptions` carries no credentials property and nothing
> is wired into the `IAuthScheme` pipeline. Authentication is instead an opt-in HTTP Signature
> `SdkHook`. The skill was rewritten around that hook and names concrete types, so it must **not** be
> copied into another APIMatic .NET plugin — take that plugin's own copy from a plugin whose SDK has
> generated auth.

> **Adding the agnostic skills to another APIMatic .NET plugin:** copy the six `dotnet-*` directories
> other than `dotnet-authentication` as they are. Everything SDK-specific — install method, root
> namespace, environments, the auth mechanism, the map, and any "this SDK doesn't generate X" caveats
> — belongs in that plugin's own getting-started skill, the way `visa-getting-started` carries it here.

## Skills

- **integrate-visa** — orchestrator/router. Routes every Visa/CyberSource .NET SDK task — planning,
  contract questions, and SDK errors — to the single `visa-sdk` agent, and drives the
  implement-and-verify loop. Grounds every fact in the contract sheet the agent produces — never model
  knowledge, and never the map directly.
- **visa-getting-started** — install (the `APIMatic.VisaCyberSource` NuGet package), the single
  `Production` environment and its sandbox-defaulting base URL, the bundled SDK map, and how to clone
  the SDK source only on a map gap. The helper-facing entry point.
- **dotnet-client-initialization** — construct `{Api}Client` + `{Api}ClientOptions`, supply an
  `HttpClient`, pick a server environment, register in DI.
- **dotnet-authentication** — **this SDK generates no auth scheme.** Enabling and debugging the opt-in
  HTTP Signature `SdkHook`: its four environment variables, exactly what it signs, and why a missing
  variable must stop the app from starting.
- **dotnet-calling-endpoints** — method-signature conventions, building request `record`s, enums,
  reading responses.
- **dotnet-models** — polymorphic `OneOf`/`AnyOf` union types, collections, dates/converters, string-
  and int-enums, unknown-field behavior.
- **dotnet-error-handling** — catching `SdkException<TError>`, reading typed errors and `RawError`.
- **dotnet-configuration-resilience** — retries, timeouts, pagination, logging.
- **dotnet-testing** — unit-test SDK calls by injecting a fake `HttpClient` / `HttpMessageHandler`.

## Agents

- **visa-sdk** — the single SDK agent. Grounds every contract in the bundled map (cloning the SDK
  source only when the map can't settle a fact), writes a contract-grounded `visa-plan.md` before any
  code is written, answers narrow contract questions, and fixes SDK compile/build errors in place —
  building to verify. No MCP.

## Install

```
/plugin marketplace add apimatic/plugin-marketplace
/plugin install visa-sdk@apimatic
```

Then ask a usage question (e.g. *"how do I raise a CyberSource invoice in C#?"*) to trigger the
relevant skill.
